Tu parte para probar la sincronización con GitHub

Prepara un repositorio pequeño, conserva los datos de tu teléfono y crea la credencial únicamente cuando la APK ya tenga el campo seguro. La app descargará documentos para leerlos sin conexión; tus notas y anotaciones seguirán locales.

1 Ahora: elegir contenido de prueba

Al comunicar la selección al agente basta con repositorio, rama y carpeta. No hace falta dar acceso ni credenciales en el chat.

2 Antes de instalar la APK

No desinstales para resolver un error de firma hasta tener respaldo verificado y un plan de restauración. El certificado debug puede cambiar entre computadoras.

3 Cuando la app ofrezca «Conectar GitHub»

  1. Desde un navegador de confianza, abre GitHub · Fine-grained personal access tokens e inicia sesión.
  2. Elige el Resource owner correcto, Only select repositories y únicamente los repositorios de prueba.
  3. Concede Contents: Read-only y Metadata: Read-only. No concedas escritura, Actions ni Administration. Usa un nombre como Hyper-Marker Android Read Only y una expiración razonable.
  4. Pega el token directamente en el campo seguro de la APK. Después selecciona repo, rama y carpeta dentro de Hyper-Marker.

Nunca pegues el token en Codex/ChatGPT, issues, capturas, commits o este HTML. Si un repo nuevo no aparece, revisa su autorización en los ajustes del token de GitHub y actualiza la lista en la app.

5 Al terminar las pruebas

Si ya no usarás la conexión, revoca el token desde GitHub · tus tokens y desconecta la cuenta en Hyper-Marker. Desconectar la app elimina la credencial local; la revocación del token ocurre en GitHub.

Comparte el resultado de cada prueba, la rama y el tipo de archivo. Nunca incluyas la credencial ni rutas privadas completas en capturas o reportes.

Lista imprimible y local: las casillas no guardan información. Basada en la especificación de sincronización. La disponibilidad de cada paso de la app depende del hito implementado y validado.
