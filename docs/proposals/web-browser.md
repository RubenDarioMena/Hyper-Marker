# Navegación HTTPS, copias offline y Abrir con HTML

Cambio autorizado por el propietario el **2 de noviembre de 2026**; complementa la especificación original, que permanece intacta. Se permite esta ampliación pese a la aceptación manual V1 aún pendiente.

## Comportamiento

- Acceso «Navegar por la web» / «Buscar o abrir una página web» en la biblioteca y en el menú del lector. La barra acepta URL HTTPS, dominio sin esquema o búsqueda en DuckDuckGo. Atrás, adelante y recargar; Atrás del sistema recorre el historial antes de salir. El navegador tiene barra visible mientras se navega; el lector local conserva sus controles transitorios.
- Los enlaces HTTPS tocados en el lector abren el navegador independiente. Un script del documento no inicia esa transición sin gesto del usuario.
- Los nuevos HTML importados y los nuevos paquetes HTML de GitHub permiten recursos HTTPS/WSS por defecto. No hay migración de los valores guardados ni se revierten revocaciones anteriores. Duplicados y copias locales de GitHub conservan el comportamiento offline anterior; las capturas web siempre son offline. No hay cambio de esquema Room.
- «Descargar página» captura el MHTML del WebView y publica una copia `WEB_SNAPSHOT` en la carpeta actual sólo después de convertirla correctamente. «Estudiar copia» abre el lector habitual, con pines, sustituciones de texto y dibujos separados del contenido. «Abrir página original» vuelve al navegador.
- La copia conserva el MHTML recibido en `capture/page.mhtml`, URL/fecha en `web-source.json` y una representación HTML con recursos locales en `original/`. Recursos con nombres generados, sin usar rutas del MIME. Copiar/renombrar/mover/borrar funcionan con la biblioteca existente. Fallos compensan archivos y no publican filas parciales.
- Android recibe `ACTION_VIEW` para MIME `text/html` y `application/xhtml+xml` mediante `content://` y `file://`, además de Compartir. Se copia la fuente por el importador existente. HTML, HTM y XHTML son entradas admitidas. URI `file://` sólo permite rutas canónicas bajo `/storage/`; no se añaden permisos generales de archivos. Un proveedor moderno debe conceder acceso temporal al URI `content://`. El aspecto exacto del selector depende del gestor de archivos y de las aplicaciones predeterminadas del usuario.

## Límites y seguridad

El navegador remoto carece de AssetLoader y bridge; tiene `file/content` deshabilitados, no concede permisos web, no acepta popups ni esquemas externos, bloquea HTTP claro y hosts privados `*.hypermarker.invalid`. Mantiene cookies deshabilitadas globalmente para conservar el aislamiento del lector. No hay sesiones de acceso persistentes: sitios que necesitan cookies, almacenamiento persistente, descargas de adjuntos, PDF nativo, ventanas nuevas, DRM o permisos pueden no funcionar. Es un navegador integrado para estudiar páginas compatibles, no una promesa de compatibilidad universal.

Las copias son **capturas de contenido ya cargado**, no una descarga recursiva del sitio ni una réplica funcional de una aplicación remota. No se garantizan vídeos, canvas/WebGL, frames, recursos aún no cargados, ejercicios que dependen del servidor, formularios ni navegación a páginas no descargadas. Se reescriben referencias HTML/CSS y `cid:` capturadas a rutas locales; faltantes permanecen bloqueados. Los scripts de la página guardada y los frames no se ejecutan, aunque el controlador de anotaciones nativo sí se instala. La CSP impide red/scripts originales/formularios; el WebView bloquea red y el repositorio rechaza habilitarla en `WEB_SNAPSHOT`. No se depende de la caché de navegación.

Límites de conversión: archivo MHTML de 32 MiB, 10 MiB por recurso decodificado, 32 MiB decodificados, 2.000 partes y cabeceras acotadas. El archivo que genera Chromium se valida al terminar; `saveWebArchive` no ofrece cancelación ni cuota durante su escritura. La UI bloquea navegación táctil y acciones mientras guarda (hasta 45 s); no se promete un límite estricto del archivo temporal antes del callback. El directorio temporal se limpia al finalizar y en recuperación tras reinicio. La publicación final usa el mutex del repositorio. El MHTML y los recursos extraídos ocupan espacio adicional.

API empleada: [Android WebView.saveWebArchive](https://developer.android.com/reference/android/webkit/WebView#saveWebArchive(java.lang.String,%20boolean,%20android.webkit.ValueCallback)). Contexto del serializador: [Chromium Save Page As](https://chromium.googlesource.com/chromium/src/+/main/content/browser/download/docs/save-page-as.md). No se añade una dependencia de terceros.
